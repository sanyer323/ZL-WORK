## 2026-09-20 首轮（讲解片 ≠ 宣传片 + 成片可核对口径）

### 研发仿真片和营销片不是同一条流水线
- 仓库 `AI研发产品/研发仿真视频/README.md` 写明：基于 FY301ME 与脚本，做**可计算仿真**，不是营销三维宣传片。
- 现成对照：`旁白文案_原理讲解版.txt`（本段要点=机理）vs `旁白文案_工程师培训版.txt`（现场结论=坏了查哪）。
- **坑**：用「钩子-痛点-产品-下单」剪研发片，或把排故五步硬塞进原理版——观众会以为在看广告或维修手册，机制没讲清。

### 成片编码：跟官方上传建议对齐，别跟二手码率表
- YouTube Help《Recommended upload encoding settings》（核对日 2026-09-20，`support.google.com/youtube/answer/1722171`）：容器 **MP4**（moov 前置 / Fast Start）；视频 **H.264** High Profile、逐行、4:2:0；音频 **AAC-LC**（或 Opus），**48 kHz**；电脑端标准画幅 **16:9**；SDR 1080p 常帧率（24/25/30）建议约 **8 Mbps**，高帧率约 **12 Mbps**。帧率跟源一致，不要把仿真 30 fps 强拉成 60。
- 仓库成片脚本已是 `libx264` + `yuv420p` + `aac`，和这条兼容；不必为「看起来更专业」改去跟未经核对的博客码率表。
- **坑**：B 站具体 Mbps / 是否强制整数帧，今天只搜到二手教程且互相打架，**没有官方投稿白皮书可核对 → 不入库数字**。跨平台先守 H.264 + AAC + MP4 + 16:9。

### 烧录字幕 ≠ 软字幕；SRT 要纯文本
- 仓库已分两路：`FY301_研发原理讲解_完整版.mp4` 用 ffmpeg `subtitles=` **烧进画面**；`FY301_研发原理讲解_软字幕.mp4` 另挂字幕轨。讲解默认走软字幕，方便关字幕看曲线。
- YouTube Help《Supported subtitle and closed caption files》（核对日 2026-09-20，`support.google.com/youtube/answer/2734698`）：`.srt` 只认基础时间轴，**不认样式标记**，须 **UTF-8**。
- WCAG 2.2 SC **1.2.2 Captions (Prerecorded)**（W3C Recommendation 2023-10-05；现行 TR 页标注 2024-12-12，`www.w3.org/TR/WCAG22/`）：有对白的预录片要同步字幕；字幕含必要非语音信息；**不得挡住理解内容所需的画面**。
- **坑**：只出烧录版、字幕压在 FYCAL 曲线/数值上；或把 ASS 花字写进要上传的 `.srt`。
## 2026-09-23 首轮（仿真成片 + 外发编码 + 字幕/响度）
### 研发仿真片 ≠ 营销片
- 本仓库 README 写明：基于 FY301ME 手册的**可计算仿真**，不是营销三维宣传片。成片价值是「能对上手册数字、能复现」，不是「好看」。
- **坑**：用产品宣传分镜（痛点→方案→卖点）去剪原理片，数字和极性会被台词挤掉。
### 原理口吻和排故口吻不要混
- 仓库已拆两版：`build_principle_edition.py`（机理要点） / `build_engineer_edition*.py`（现场结论）。旁白文件也是两套。
- **坑**：同一条片子前半讲「电压升高先导压升高」，后半突然改「先别怪气源」——观众不知道这是课还是排故单。
### 外发成片：按 YouTube 官方上传编码，不要抄博客
- 核对日 2026-09-23，来源：[YouTube Help · recommended upload encoding](https://support.google.com/youtube/answer/1722171?hl=en)
- 容器 **MP4**；**不要 Edit Lists**（否则可能处理失败）；**moov atom 放文件头**（Fast Start）。
- 视频：**H.264**，逐行、High Profile、连续 2 个 B 帧、**Closed GOP（GOP = 帧率一半）**、CABAC、VBR、色度 **4:2:0**。官方写明**没有强制码率上限**，表是参考。
- SDR 1080p 参考码率：常帧率（24/25/30）**8 Mbps**；高帧率（48/50/60）**12 Mbps**。内部培训片不必为了「像 YouTube」硬抬码率。
- 音频：AAC-LC / Opus / Eclipsa Audio；**采样率 48 kHz**；上传参考码率：单声道 128 kbps、立体声 **384 kbps**、5.1 为 512 kbps。
- 本仓库现成脚本多是 `libx264` + `yuv420p` + `aac` `128k`。**128k 是官方单声道参考，不是立体声上传参考**；对内交付够用，外发再加。
- **坑**：把博客「2026 最佳码率」当官方；或把内部 128k 立体声说成「已经按 YouTube 官方」。
### SDR 用 BT.709，别给 matplotlib 片打 HDR 标签
- 同一官方页：SDR 上传推荐色彩空间 **BT.709**（TRC / primaries / matrix 都按 BT.709）。未标明时平台会按 BT.709 猜；乱标 BT.2020 / HDR 会被转回 8-bit BT.709，还容易色带。
- 官方不推荐上传带 **RGB color matrix**。本仓库仿真是 matplotlib / PIL 出帧，按 SDR、yuv420p 走即可。
- **坑**：把「更高级」理解成打 HDR 标签。讲解片没有高动态，标了只会坏。
### 帧率跟源走；本仓库仿真默认 20 fps，不要为平台强升 30
- YouTube 官方：按**拍摄/生成时的帧率**编码上传；常见 24/25/30/48/50/60，并写明**其他帧率也可**。隔行要先去隔行。
- 仓库 `render_sims.py` / `build_principle_edition.py` 等 **FPS = 20**。20 fps 对机理动画够用。
- **坑**：成片时 `-r 30` 却不重渲，等于插帧或抽帧；字幕时间轴和旁白时长会对不齐。拼接用 concat 时，各段帧率先统一。
### 字幕：SRT 用纯 UTF-8、不要样式；软字幕优先
- 核对日 2026-09-23，来源：[YouTube Help · supported subtitle files](https://support.google.com/youtube/answer/2734698?hl=en)
- SubRip `.srt`：只支持基础版，**不认 markup/样式**，必须是 **plain UTF-8**。仓库脚本已 `encoding="utf-8"` 写 SRT，保持。
- 烧录字幕（open captions）改不了、挡画面；软字幕轨（closed captions）可开关、可后改。仓库 README 已分「烧录」和「软字幕」两份成片。
- WCAG 2.2 **SC 1.2.2 Captions (Prerecorded)**（Level A）：同步媒体里预录声音要有字幕，除非片子只是页面正文的替代且已标明。来源：[W3C Understanding SC 1.2.2](https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html)（核对日 2026-09-23）。
- **坑**：在 SRT 里塞 HTML/ASS 样式指望平台认；或只有烧录、没有独立 SRT——下次改一句旁白要重渲整片。
### 响度：用 BS.1770 量；广播目标是 −23 LUFS，不是「YouTube 官方 −14」
- **怎么量**：ITU-R **BS.1770-5**（2023-11，现行）规定节目响度和真峰值算法。来源：<https://www.itu.int/rec/R-REC-BS.1770/>
- **广播怎么对齐**：EBU **R128-2020**（2020-08）节目响度目标 **−23.0 LUFS**（实务容差 ±1.0 LU），生产环节真峰值 **不超过 −1 dBTP**。来源：EBU R128 PDF（核对日 2026-09-23）。
- YouTube 帮助页**没有**公布 −14 LUFS。网上当「官方」传的是社区逆向，**不入库当规范**。
- 对本仓库：Windows SAPI / ffmpeg 混音常见峰值顶满。下次至少：**真峰值留余量，不要 0 dBFS 削顶**；外发广播/电视台再套 −23 LUFS。内部培训片不必为了响去压限。
- **坑**：按峰值表把旁白推到满幅，换播放器就炸；或把未公开的平台归一化目标写成官方。
### B 站：能核对的是上限，不是推荐码率
- 开放平台投稿接口「注意事项」写的是限制：封装建议 mp4/flv、峰值码率最大 60 Mbps、yuv420、建议逐行、音频最大 320 kbps / 2 声道 / 48 kHz、关键帧至少 10 秒一个。这是**上限**。
- 社区帖里的「1080p 推荐 6 Mbps」互相打架，**没有帮助中心成片推荐表可核对**，不写进配方。
- **坑**：把 60 Mbps 峰值上限当成目标码率，讲解片又大又慢，没有更清楚。

- W3C WebVTT（CRD 2026-05-20，`www.w3.org/TR/2026/CRD-webvtt1-20260520/`）：网页播放器用 `.vtt`，文件体必须 **UTF-8**，首行 `WEBVTT`，毫秒用 **点** 不是逗号。仓库现成片是 `.srt`，上传/网页各跟各的格式，不要改后缀冒充。

- 本仓库已有烧录版与软字幕版。默认出 **可开关软字幕**；烧录只作不能挂轨的场合。
- **坑**：用 GBK 存中文 SRT；把 ASS 花字当 YouTube 字幕；只烧录、观众关不掉。

- **坑**：拿峰值表当响度；把博客里的「油管 −14」写进交付清单。
### B 站只记官方上限，不记推荐码率

## 2026-09-30 首轮（16 kHz 旁白、20 fps GOP、中/欧响度靶分开）
### 本仓库旁白默认 16 kHz；外发要重采样到 48 kHz
- 现成脚本把 TTS / 静音轨统一成 **16 kHz 单声道** 再 concat：`add_sapi_voice.py`、`build_principle_edition.py`、`build_engineer_edition*.py` 都是 `anullsrc=r=16000` 且 `-ar 16000`。混音出口径 AAC **没有** `-ar 48000`。
- YouTube Help《recommended upload encoding settings》（核对日 2026-09-30，`support.google.com/youtube/answer/1722171`）：音频采样率 **48 kHz**。
- ffmpeg concat demuxer 官方说明（`ffmpeg.org/ffmpeg-formats.html#concat`）：**所有文件必须同一套流**（同一编码器、同一时基等）。脚本先归一到 16 kHz 再 `-c copy` 拼接，对内是对的；**不要把「拼接能过」当成「外发采样率也对」**。
- **坑**：对内 16 kHz 能听、能拼，就标「已按 YouTube 官方」；或拼接时一段 16 kHz、一段 48 kHz 还 `copy`，时间轴会漂。

### 20 fps 的 Closed GOP 是 10 帧，不是抄 30 fps 的 15
- 同一 YouTube 官方页：H.264 **Closed GOP**，**GOP = 半帧率**；另要 High Profile、连续 2 个 B 帧、Fast Start（moov 在文件头）、**不要 Edit Lists**。
- 本仓库源是 **20 fps** → 半帧率 = **10 帧（0.5 秒）**。外发不要拿 24/30 fps 教程里的 GOP=12/15 来套。
- Fast Start 在 ffmpeg 里就是 `-movflags +faststart`（官方 muxer 说明：把 moov 挪到文件头）。现成成片命令没加这一项。
- ffmpeg mp4 写入可用 `use_editlist=0`（默认 auto）。YouTube 写明有 Edit Lists 可能处理失败。
- **坑**：给 20 fps 仿真片套 30 fps 的 GOP 表；或只口头说 Fast Start，成片里没有 `+faststart`。

### 响度：尺子是一把，靶按交付地；量用 ebur128，不要用 loudnorm 默认值冒充 R128
- **怎么量**：ffmpeg `ebur128` 是 EBU R128 扫描器（官方 filters 文档 `ffmpeg.org/ffmpeg-filters.html#ebur128-1`，核对日 2026-09-30）。看 Integrated loudness（`I`，LUFS）和真峰值（`peak=true` 时的 `TPK`）。这是尺子，不是自动压到某个靶。
- **坑**：用 `volumedetect` 的 mean/max 当响度。mean 不是门控积分响度，max 不是真峰值。
- **欧广电靶**：EBU **R 128 v5**（2023-11，`tech.ebu.ch/docs/r/r128.pdf`）仍是节目响度 **−23.0 LUFS**、生产真峰值 **不超过 −1 dBTP**。脚注写明 **LUFS = LKFS**（ITU-R BS.1770 用 LKFS）。流媒体另有补充文件 s2，那是欧广电对流媒体的建议，**不是 YouTube 帮助页**；YouTube 仍未公布上传响度靶。
- **中国数字电视靶**：GY/T **282-2014**《数字电视节目平均响度和真峰值音频电平技术要求》（广电总局页标注现行有效，`www.nrta.gov.cn/art/2020/4/29/art_3715_50938.html`；标准文本 4.3–4.6）：平均响度 **−24 LKFS**、容差 **±2 LU**、整片真峰值 **不超过 −2 dB TP**。量法按 GY/T 262。
- **ffmpeg `loudnorm` 默认**（同一份 filters 文档）：目标 I=**−24.0**、真峰值 TP=**−2.0**。这接近 GY/T 282 / ATSC，**不是** R128 的 −23 / −1。不改参数就跑 loudnorm，等于偷偷套了中国电视靶。
- 本仓库成片是单声道旁白。ffmpeg 写明：单声道若按立体声系统回放，R128 读数会偏，需 `dualmono=true` 才补偿。对内用耳机听 SAPI，不必为了广播去开。
- **坑**：内部培训片按 −23 压限；给国内电视台交片却抄 R128 的 −1 dBTP；或把 loudnorm 默认输出当成「已经符合 R128」。
## 2026-10-04 周日通读（外发章节，不重抄码率）
### YouTube 章节写在描述里，不靠自动切
- YouTube Help《Video Chapters》（核对日 2026-10-04，`support.google.com/youtube/answer/9884579`）：创作者可自己加章节，也可靠自动章节；**手写列表会覆盖自动章节**。自动章节默认对新手上传勾选，但**不是每条视频都有资格、有资格也不一定生成**。

- 本仓库原理/培训片已是多段仿真。外发时章节名跟编剧段名走，不要写成「产品亮点 1」。
- 对内 mp4 有章节路标、能按段跳即可；**不必**为了对内播放去嵌 MP4 chapter atom。
- **坑**：只开自动章节，平台按画面切，把「先导压」和「滑阀」粘在一起；或第一条写成 `0:15` 开场，整表不生效。
## 2026-10-07 周三（外发挂字幕、色域标记、AI 披露）
### 外发字幕：上传带时间轴的 SRT，不要 Auto-sync / 自动字幕当验收
- YouTube Help《Add subtitles & captions》（核对日 2026-10-07，`support.google.com/youtube/answer/2734796`）：Studio → Subtitles → ADD LANGUAGE → ADD。选 **Upload file** 时可选 With timing / Without timing。仓库已有带轴 `.srt`，走 **With timing**。
- 同一页的 **Auto-sync**：把逐字稿丢进去，由语音识别对轴，对齐完成后**自动发布**。官方写明稿子必须是片里说的那种语言，且不推荐超 1 小时或音质差的片。SAPI / 工业术语（FYCAL、Hall、先导压）对不上语音识别 → **不要用 Auto-sync 代替现成 SRT**。
- YouTube Help《Use automatic captioning》（核对日 2026-10-07，`support.google.com/youtube/answer/6373554`）：**鼓励先交专业字幕**。自动字幕若能生成，会**自动发布**；质量因口音、发音、噪声而异，**可能歪曲原话**。自动字幕只跟视频的 **default language**。中文旁白却把视频语言留成英语，自动轨会按错语言生成。
- 同一页：看不懂或术语错了，在 Subtitles 里改或删。删轨见《Edit or remove captions》（`support.google.com/youtube/answer/2734705`）：Options → Delete。
- 本仓库现成成片已经有独立 UTF-8 SRT。外发验收看**上传轨**，不看自动轨。
- **坑**：只交 mp4、等自动字幕；或把 `旁白文案_*.txt` 丢进 Auto-sync，时间轴漂、FYCAL 被听成别的词，还自动上线。

### 外发色域：BT.709 写进文件头；full range 会被平台压成 limited
- YouTube Help《recommended upload encoding settings》（核对日 2026-10-07，`support.google.com/youtube/answer/1722171`）：SDR 推荐 **BT.709**，TRC / primaries / matrix 都是 BT.709（H.273 值 1）。**未标明 TRC / matrix / primaries 时，平台按 BT.709 猜**。
- 同一页：**不推荐上传带 RGB color matrix**；遇到 RGB 会先把 matrix 当成未指定，再按 primaries 猜。**sRGB TRC 会被转成 BT.709 TRC**。不支持的色域会转回 8-bit BT.709，BT.2020 这类还容易色带。
- 同一页原句：**YouTube converts full color range to limited color range.** matplotlib / PIL 出帧是电脑全范围 RGB；现成脚本只 `-pix_fmt yuv420p`，文件头通常没打 `color_primaries` / `color_range`。外发时要标 BT.709，像素走 limited（tv）。只改标签、像素仍是全范围，或像素已是 limited 却标成 full，曲线和白底字会洗掉或夹死。
- ffmpeg `colorspace` 滤镜（官方 filters 文档 `ffmpeg.org/ffmpeg-filters.html#colorspace`，核对日 2026-10-07）：输出范围 `range=tv`（limited）或 `range=pc`（full）；`all=bt709` 一次标齐。这是改像素+标签，不是口头说「按 BT.709 理解」。
- 对内培训片未标也能播。**真要上传**再标；不要给仿真片打 HDR / BT.2020。
- **坑**：以为「yuv420p 就等于已经 BT.709」；或把 RGB matrix / full range 原样丢上去，让平台再压一次。

### 外发「AI use」：机理仿真 + 系统旁白不是强制披露的写实 AI
- YouTube Help《Disclosing use of GenAI content》（核对日 2026-10-07，`support.google.com/youtube/answer/14328491`）：必须披露的是 **用 AI 实质性改写或生成、看起来像真的** 的内容（真人没说过的话、改真实事件/地点、生成并未发生的写实场景、以及以 AI 音乐为主的片子）。
- 同一页写明 **非写实、或只是小改，不必披露**。官方「不必披露」举例包括：全动画片里的 AI 动画、用生成工具写大纲/脚本/字幕、**克隆自己的声音做旁白或配音**。本仓库 matplotlib 机理片 + SAPI 旁白落在这一侧。
- 上传时在 Attributes → **AI use** 选 Yes / No。机理讲解片选 **No**。画面改成写实合成、或让真人「说了没说过的话」，再改口。
- 官方也写：不披露写实 AI 可能被补标、下架或影响 YPP；系统也可能误标，多数情况可在 Studio 改回 No。
- **坑**：因为用了 TTS 就一律勾 Yes（把培训片标成伪造）；或做成写实深伪却勾 No。
