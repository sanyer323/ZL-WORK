# 卖 AI 算力 · 落地方案

**版本**：2026-10-20  
**负责人**：AI-海外业务（卖 AI 算力）  
**主体**：香港公司收款；上游百度官方供给  
**状态**：成本单价未确认；书面授权未拿到。对外报价一律占位，不锁死客户价。

本文把「官方折扣 × 港司收款 × 百度供给」收成可执行方案。主线是 Token / 调用额度渠道；AI 服务标品是期权。90 天资源按 **主线 : 期权 = 7 : 3**。

不在本文写入任何 API Key。国内试用 Key 只称「百度主账号 Key」，不裸分发。

## 1. 商业模式

### 1.1 卖什么

客户买的是**我方港司名下的预充值虚拟额度**，不是百度原厂 Key，也不是无限包月。

```
客户预充 USD → 港司账户
        → 我方网关发客户 Key，按调用扣额度
        → 网关用百度主账号 upstream 按量结算
        → 客户拿不到百度控制台、拿不到原厂 Key
```

已测通的上游形态（国内，自用验证，不是对外承诺）：BO-Response / Chat Completions，端点在国内智能点播侧。已打通过的模型包括 gpt-5.5、gpt-5.6-sol / luna / terra、gpt-6-astra。**账单尚未出现这些模型的人民币单价行**，计量像 token，但是否与「视频生成积分」同一套账，待次日账单与百度书面答复。

本机 Hermes 桥（仅本机回环）是自用壳，**不是**对外产品，也不能直接挂到 OpenRouter。

### 1.2 定价：成本未知时怎么占位

对外现在只说三句：

1. 预充值、按量扣费，余额用尽即停。  
2. 价目以「我方结算成本确认后公示」为准，**不接受按猜测单价锁年框**。  
3. 目标毛利带：售价 = 成本 × **1.5～1.8**（对应毛利率约 33%～44%），再扣支付与客服。

变量（禁止填假单价）：

| 符号 | 含义 | 现状 |
|------|------|------|
| `C_in` / `C_out` | 百度渠道结算价，按模型、按输入/输出 | **待确认**（公开价目与控制台均无 gpt 系列 RMB 行） |
| `P_in` / `P_out` | 我方对客户售价 | 暂不公示 |
| `M` | 加价倍率，`P = C × M`，`M ∈ [1.5, 1.8]` | 已定区间 |
| `f_pay` | 收款手续费占比 | 暂按约 3% 做敏感度，以港司实际通道为准 |
| `f_ops` | 客服 / 对账 / 坏账准备 | 暂按约 6% |
| 贡献利润率 | `1 − 1/M − f_pay − f_ops` | M=1.6 时约 28.5%（示意，不是实账） |

拿到 `C` 之后，每个模型做一张表再决定上不上架：

```
批发建议价 ≤ min(C × 1.6,  海外公开锚价 × 0.9)   # 给中转站留毛利
零售建议价 = C × 1.6～1.8                          # 直接客户
若 C × 1.5 已高于海外公开锚价 → 该模型暂不上架
```

海外公开锚价（如 OpenRouter、Bedrock Global）只作**天花板对照**，不是我方成本。千帆文本模型目录价与 OpenAI / Bedrock 官网价**不是同一张表**：币种、单位、SKU 都不同。gpt 系列目前不在已核对的千帆公开目录行里，不能用文心 / DeepSeek 目录价去乘 6.5 折当成 gpt 成本。

### 1.3 代金券

账号内有后付费通用代金券（面额与有效期以控制台为准）。适用范围写明智能分析 / 带宽 / 存储 / 视频生成，**未点名** BO-Response / 对话调用。

- 试用可以继续打，用来验证「次日账单长什么样」。  
- **不能**把券余额当成可售成本，也不能向客户承诺「券价」。  
- 券是否覆盖 chat / OC，是商务会的优先问题，未书面确认前按「不覆盖」做资金准备。

### 1.4 什么时候可以对外报价

同时满足才出正式价目：

1. 百度书面给出该模型的**计费项名 / SKU / 渠道单价**（输入、输出分开）。  
2. 至少一张真实账单能对上同一次调用的 token 与金额。  
3. 书面允许「网关分账 + 官方 upstream」面向约定客户范围销售。

在此之前，种子客户只收**小额预充意向**或内部试用，合同写「单价以书面价目附件为准，附件出具前可退预充」。

## 2. 分阶段路线图

### 0～30 天 · 把闸门钉死（主线约 7 成精力）

| 动作 | 闸门 / 验收 |
|------|-------------|
| 按《百度商务沟通提纲》开会：身份、结算、落户产品、出海、品牌 | 五件事均有邮件 / 合同附件 / 函件，不是聊天口头 |
| 优先问清 BO/gpt 计费项名、公开价与渠道价；券是否覆盖对话 | 书面 SKU 表；券覆盖范围书面是或否 |
| 用主账号打一笔可追溯调用，次日对账单 | 账单行能对应模型、用量、金额；对不上则暂停对外 |
| IT 出网关最小可用（见第 3 节），先只给内部 Key | 流式补全 + usage 回传 + 额度扣减可对账 |
| 港司收款路径跑通一笔小额（可退） | 银行 / 收款工具入账凭证 |
| 期权线只做「选一个标品方向」的客户痛点清单，不开发 | 不超过 3 成时间；无对外交付承诺 |

**不过关就不做的事**：不对境外客户承诺「百度直供」；不把原厂 Key 交给任何人；不向 OpenRouter 提交 Provider 申请。

### 30～60 天 · 种子预付（仍以主线为主）

| 动作 | 闸门 / 验收 |
|------|-------------|
| 书面授权里「允许网关转售」为是 | 否则本阶段只做自用，不发展客户 |
| 3～5 个种子客户，港司预充值，发我方 Key | 每户有合同 / 确认邮件、入账、Key、余额台账 |
| 每周对账：我方扣减合计 vs 百度账单 | 差异可解释（时区、缓存、失败重试）；差异过大则停新客 |
| 模型白名单只上「有单价且账单验过」的 ID | 未验过的 gpt / 国产模型不进 `/v1/models` |
| 期权：若已有真实重复痛点，用现成工具做 1 家手工样板 | 不新招人、不自研平台 |

### 60～90 天 · 可复制，再谈分销

| 动作 | 闸门 / 验收 |
|------|-------------|
| 种子客户至少 1 户续充 | 证明不是一次性试用 |
| 网关日志可按客户、模型、日导出 | 投资人 / 百度对账都能用同一份口径 |
| 视书面授权，再评估 OpenRouter Provider | 申请材料里的公网 API 已稳定；百度允许报备第三方聚合 |
| 期权：第 2～3 家若仍是「配置而非重做」，才保留 3 成资源 | 否则期权降到维持，资源回到主线 |

## 3. 技术架构

### 3.1 目标形态

```
客户 (OpenAI SDK)
  → HTTPS  api.<我方域名>/v1
       鉴权（客户 Key）
       余额 / 项目额度
       限流、审计日志
       模型白名单与我方售价
  → 百度主账号 upstream（官方 endpoint，服务端持有，不下发）
  → 按 usage 扣客户额度；原始请求记入对账库
```

后续扩展点（不是第一步）：同一网关再对 OpenRouter 暴露 Provider（`/v1/chat/completions` 含流式与 usage，`/v1/models` 含定价）。OpenRouter 的 Private Endpoint 只适合企业自己用，**不是**对外卖的路径。申请 Provider 的通过率对「百度中转 gpt」不确定，且必须先有百度许可。

### 3.2 和现状的关系

| 现状 | 对外方案里怎么用 |
|------|------------------|
| 国内 Key 已通 BO-Response | 只放在网关服务器的密钥管理里，轮换、权限最小化 |
| 可多开 Key（控制台上限内） | 仅内部分环境（试、生产），**不**按客户拆原厂 Key |
| 百度账单不能按 Key 筛选 | 对账以**我方网关日志**为准；百度账单只做总额与抽查明细 |
| 无子账号拆账单实践 | 不依赖百度子账号给客户；客户隔离在我方项目 / Key |
| 海外站要另注册、国内 Key 不能调海外 | 0～30 天先确认国内 endpoint 是否允许境外调用；不允许则等海外 endpoint，不擅自承诺低延迟 |
| Hermes 本机桥 | 保持自用；公网网关不复用该回环地址 |

### 3.3 交给 IT 的最小改造清单

按这个顺序做，做完即可内部验收，不必先上大而全控制台。

1. **公网 HTTPS** 反向代理到网关进程（证书、只开 443）。  
2. **`POST /v1/chat/completions`**：支持流式与非流式；响应里带回 `usage`（prompt / completion tokens）。上游失败时不扣费或按明确规则扣。  
3. **`GET /v1/models`**：只列出已验价模型；字段含我方对客价格（成本未确认前此接口只对内开放）。  
4. **鉴权**：客户 Key 与百度 Key 分库存放；日志脱敏，禁止把上游 Key 打进访问日志。  
5. **额度**：预充余额、按模型单价扣减、余额不足 402 / 明确错误码；管理端可手工加余额（对应港司入账）。  
6. **限流**：按客户 Key 的 RPM / TPM，防止单 Key 打穿主账号。  
7. **日志**：时间、客户 Key id（不是明文全文）、模型 id、usage、扣费金额、上游请求 id、HTTP 状态。保留不少于对账所需周期。  
8. **对账导出**：按日 CSV：客户、模型、in/out tokens、扣费、上游 id。  
9. **密钥**：上游 Key 放密钥管理或环境变量，不进仓库、不进镜像层明文。  
10. **暂不做**：OpenRouter 上架、多区域、自动开票、给客户百度控制台。

验收脚本：用内部 Key 打一次流式对话，台账 tokens 与百度次日账单抽查一致（在 SKU 已能辨认的前提下）。

## 4. 收款与合规

| 项 | 做法 |
|----|------|
| 收款 | 香港公司抬头；种子期预充值。不做后付，不做无限包月 |
| 发票 / 收据 | 按港司可开具的形式；合同写明卖的是「API 调用额度」不是百度官方订阅 |
| 币种 | 客户侧 USD（或港司实际可收币种）；上游按百度结算币种。汇差单独记，不吞进「模型毛利」 |
| 跨境数据 | 提示词与补全会进入百度国内 endpoint（在海外 endpoint 未开通前）。未拿到百度对「境外客户」的书面意见前，不签企业 DPA、不接敏感行业 |
| 内容安全 | 默认百度侧审核；我方记录违规错误码。封禁粒度先按我方客户 Key，避免一户违规拖死主账号的处置要问清百度 |
| 品牌 | 未授权前不写「百度官方」「Powered by 百度」 |
| 红线 | 无灰通道、无裸发原厂 Key、无未授权转售、无用代金券余额对外锁价 |

## 5. 风险与未决（谁来关）

### 5.1 等百度书面答复（不开工招商）

1. 合作身份名称，以及港司能否直接签。  
2. 结算币种、发票、折扣档、调价通知期。  
3. 授权是否包含 BO-Response / Chat Completions 与已测 gpt 模型；国内 endpoint 能否被境外调用。  
4. 面向境外客户是否允许；数据与出口管制责任怎么分。  
5. 品牌可用与禁用表述。  
6. **计费项名、SKU、公开价、渠道价**（按模型，in/out）。  
7. 智能点播类代金券**是否覆盖对话**；不覆盖时对话走哪条产品。  
8. 挂第三方聚合（OpenRouter Provider）是否要单独报备。

### 5.2 等账单（IT / 财务，不猜单价）

1. 10 月流水曾全为 0，因 Key 启用晚、账单未出。次日（及后续数日）账单里 gpt / BO 调用落在哪一行、单位是 token 还是积分。  
2. 该行金额 ÷ 网关记录的 tokens，反推单价，与商务报价单核对。对不上就以上游账单为准，暂停该模型上架。  
3. 账单不能按 Key 筛选：接受「总额 + 我方日志」的对账方式，还是必须让百度开项目级明细。后者未实现前，不承诺客户「百度官方分账单」。

### 5.3 我方自己的风险

| 风险 | 处理 |
|------|------|
| 口头折扣当书面授权 | 没有函件不放量 |
| 用券余额做成本 | 券未点名对话，按自有现金准备上游账单 |
| OR 价日波动，我方锁死零售价 | 合同写调价权；白名单可下架 |
| 国内链路给海外客户的延迟与可用性 | 种子期写清 best effort；不承诺 Bedrock 级 SLA |
| 主账号被单客户打满或违规连坐 | 每 Key 限额；异常熔断 |
| 期权线做成外包项目 | 见第 6 节验收；做不到配置化就停 |

## 6. 期权线怎么花那 3 成

主线 7 成：商务书面授权、账单验价、网关、种子预充、对账。  
期权 3 成：只保留一个垂直方向（AI+外贸或 AI+3D，二选一），并且遵守：

| 时间 | 期权允许做的 | 不允许 |
|------|----------------|--------|
| 0～30 天 | 列出 3～5 个真实、重复、客户愿付钱的动作；选定「标品一号」 | 招人、自研平台、对外报价包年 |
| 30～60 天 | 用现成智能体 / 我方已有额度，在 1 家手工跑通并收费 | 把主线网关需求让路给标品 |
| 60～90 天 | 第 3 家上线若明显省于第 1 家，才继续 | 否则资源收回主线 |

期权客户若要模型调用，走**同一套预充额度**，不另开灰 Key。额度是增值项，不是期权的主叙事。

## 7. 近期动作（给内部对齐）

1. 用商务提纲约百度：五件事 + 计费项 / 券，会后要书面。  
2. IT 按第 3.3 节做内网可验收的网关；上游 Key 只放服务器。  
3. 财务盯次日账单，把「计费项名 ↔ 模型 id ↔ 单价」填进内部表（本文不预填数字）。  
4. 三张表齐了（授权、单价、账单抽查）再找 3～5 个种子客户预充。  
5. OpenRouter 维持「后续分销渠道」，申请放在 60～90 天且百度点头之后。
