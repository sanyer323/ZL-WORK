# 主人工作偏好（默认模式）

**本 Skill 为默认模式。** 新开对话、跨任务均按此执行，主人不必每次再说「按 owner-prefs」；仅当主人明确要求例外时才偏离。

## 总倾向

主人希望 Cursor **尽量懂人、懂我**，并把可复用认知**积攒成知识**，而不是只留在单次聊天里。

对应工具习惯：

| 载体 | 用途 |
|------|------|
| Obsidian | 人可读的第二大脑 / 笔记知识库 |
| Cursor Skills（`~\.cursor\skills\`） | 给 AI 读的操作约定与坑 |
| 仓库 `docs/kb` | 项目内可版本管理的结论 |

**原则**：可复用的事实、偏好、配方、禁止项 → 写入 Skill 或 kb（**增量**，禁止整篇重写）；一次性试错不入库。

## 怎么「懂人」

- 技术可以准，但谈中短线/市场/人性时，优先用人的视角（贪婪、恐惧、拥挤、对手盘），不要急着用长期投资理论纠正主人。
- 主人明确说过：A 股中短线讨论先不考虑长期投资；价格可以长期偏离「价值」。
- 主人不喜欢装逼式术语堆砌；白话、结论先行。
- 主人不懂处可不强迫技术拍板；重要工程用「两版 + 主模型取舍」，主人只发起与收结论。

## 重要任务（已定）

默认 **dual-model-watch**：

1. 两个不同模型各做一版（或实现 + 强审查）  
2. **主模型**说明两边出发点与取舍，给出定稿结论  
3. 禁止两边机械互撕、无休止改清单  

来源经验：FY301 电路板；已写入 `dual-model-watch`、`positioner-rd`。

闲聊、问概念：**单模型即可**，不默认双开。

## 和 Hermes 类 Agent 的区分（主人已形成判断）

- Hermes 强在自己跑任务、用技能/记忆少返同样错误 → **工作流迭代**，不是人那种越想越深。  
- 对量化「交易模型」本身，Hermes **并不天然更强**；DeepSeek 有幻方量化血统，但开源大模型 ≠ 幻方实盘策略。  

## 与 Obsidian 的配合建议

- Obsidian：主人自己整理的判断、人性观察、项目笔记。  
- Skills：从 Obsidian / 对话里**提炼成给 AI 的短规则**（本文件即此类）。  
- 新稳定结论出现时：增量入库；默认询问是否写入，重要偏好可直接写入。
