# 多模型万无一失（两版 + 主模型）

## 经验来源（优先照这个做）

FY301 电路板：让**两个不同模型各改一版**，再问**主模型**。主模型能清楚说明两边为啥改、怎么取舍。  
主人专业知识不如模型，但需要这种**万无一失的考虑**——由主模型完成综合，而不是两边机械互传清单、无休止互改。

## 何时必须用

- FY301 / 电路 / 固件 / HART / 定位器等改贵、错不起的任务
- 单模型做完曾出错、或方案有明显分叉

普通小改不必。

## 默认流程（推荐）

```
模型 A 做一版  +  模型 B 做一版（可 /best-of-n 或两个 Agent）
        ↓
主模型（可与 A/B 不同，或同一对话里的「综合者」）阅读两版
        ↓
主模型用白话说明：各自出发点、优劣、风险、建议采用/如何合并
        ↓
按主模型结论落一版（可让 A 或 B 执行合并，主模型再看一眼）
        ↓
收工（禁止无休止互撕）
```

### 您怎么说（不懂技术也行）

开两个实现（或 `/best-of-n`）后，对**主模型**说：

```text
这是两个模型对同一任务的两版改动。请用我能听懂的话说明：
1) 各自出发点（为啥这么改）
2) 关键取舍与风险
3) 你建议用哪版，或怎么合并成一版最稳
不要让他们无休止互辩；你综合定稿，给出明确结论。
```

若只要继续执行：

```text
按你刚才的取舍结论执行合并/定稿，做完简短确认即可。
```

若要停：

```text
停。保留你已给出的取舍说明，先不改代码。
```

### 主模型输出应有的样子

- 两边各自想解决什么  
- 哪里一致、哪里冲突  
- **一个明确结论**：采用 A / 采用 B / 合并要点（列 ≤5 条）  
- 剩余风险（未验证的）用白话写清  

## 角色

| 角色 | 职责 |
|------|------|
| **实现 A / B** | 各出一版，可附简短「我为啥这么做」 |
| **主模型** | 懂两边出发点、做取舍与定稿建议；防单点盲目 |
| **主人** | 发起任务、把两版交给主模型、说「按结论执行」或「停」 |

## 禁止

- 两边无休止互传补丁清单、越改越乱  
- 逼主人做电路/固件级技术二选一  
- 主模型只说「都不错」而无明确结论  
- 用纯机械「做改一条、盯否一条」代替综合取舍（那是次选，不是默认）

## 次选（单线实现时）

若暂时只有一版：实现后用 `/agent-review` Deep，或换另一模型做一次审查。  
审查意见交给**主模型**综合「改不改、改哪些」，仍避免实现者与审查者无限拉锯。

`/best-of-n`：适合「两版竞赛」；定稿仍要主模型做取舍说明（与上节相同）。

## FY301 / 定位器

- 电路、固件骨架、HART：默认走「两版 + 主模型」  
- 细节索引：`positioner-rd` Skill  
- 可复用结论增量写入 kb，勿整篇重写  

## 收工门槛

- [ ] 至少两路独立考虑（两版实现，或一版实现 + 异模型审查）  
- [ ] 主模型给出**明确取舍结论**（主人能听懂）  
- [ ] 已按结论定稿，或主人说「停」并留下结论备查  
- [ ] 未再进入无休止互改
