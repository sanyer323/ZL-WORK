# 双模型盯梢（Doer + Watcher）

## 何时必须用

- FY301 / 定位器固件 / HART / 仿真骨架等**不可轻易返工**的任务
- 单模型做完后曾出现：编译不过、逻辑空洞、首页空白、缺测试等
- 要合并进主分支或给客户用的改动

普通小改（改文案、调样式）不必双模型。

## 角色分工

| 角色 | 做什么 | 不做什么 |
|------|--------|----------|
| **做（Doer）** | 按任务实现、自测、给证据 | 不自己「审查通过」收工 |
| **盯（Watcher）** | 对照目标查 bug、缺项、风险假设 | 不重写整单（除非做方失败需接管） |

**禁止**：同一聊天里同一模型又写又宣称审查通过。盯梢必须**新开 Agent** 或走产品内置审查。

## Cursor 里怎么做（推荐顺序）

### A. 默认盯梢（最快，日常重要任务）

1. **做**：Agents Window → New Agent → 选模型 A → 写清验收标准 → 让其做完并自测。
2. **盯**：同一会话或新会话输入 `/agent-review`，重要任务选 **Deep**。
3. 做方按审查意见改；改完再跑一次 Quick review 或让盯方确认「无阻断项」。

### B. 异模型盯梢（更稳，固件级）

1. **做**：模型 A（实现向）完成分支/提交。
2. **盯**：再开一个 Agent → 选**不同**模型 B → 提示词用下面「盯梢提示词」。
3. 盯方只出问题清单与严重级别；做方再修。
4. 上 PR 后可选 Bugbot：`cursor review` / `bugbot run`。

### C. 不要当成盯梢的

- `/best-of-n`：多模型**竞赛实现**，不是盯梢；只有「要对比多套方案」时用。

## 盯梢提示词（复制即用）

```text
你是盯梢审查员，不是实现者。审查当前分支相对 main（或指定 base）的改动。

任务目标：<粘贴原任务验收标准>
已知风险：<例如：单模型曾留下空首页 / 未编译 / 缺测试>

请输出：
1. 阻断项（必须修）：编译/链接、错误逻辑、安全、数据丢失、验收未达标
2. 应修项：缺测试、边界、接口不一致
3. 建议项：可读性/结构
4. 未验证项：你没跑过、缺环境导致无法证明的部分

规则：
- 不要重写整单；最多给最小补丁建议
- 每个问题标明文件路径
- 若无明显阻断，明确写「无阻断项」并列出你实际检查了什么
```

## FY301 / 定位器补充

- 固件骨架、HART、仿真任务：默认走 **B（异模型盯梢）** + `/agent-review` Deep。
- 验收至少包含：能编译/能跑通入口、关键模块有桩或实现边界清晰、文档/目录与仓库约定一致。
- 可复用事实仍写入 `positioner-rd` Skill 与 `ValvePositioner/docs/kb`（增量，勿整篇重写）。

## 收工门槛（盯梢通过才算完成）

- [ ] 做方给出运行/编译/测试证据
- [ ] 盯方（或 `/agent-review` Deep）无**阻断项**
- [ ] 阻断项已修且盯方复检或第二次 review 通过

## 模型配对（经验，可改）

| 做 | 盯 |
|----|----|
| 较快实现模型 | 更强推理/审查模型 |
| Cloud Agent 实现 | 本机另一 Agent 或 Bugbot 盯 PR |

具体型号随 Cursor 可选列表变；原则是 **做 ≠ 盯、模型尽量不同**。
